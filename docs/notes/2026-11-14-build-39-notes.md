# Build 39 (1.8.0) — owner notes while using TestFlight

Started 2026-11-14 on `feature/after-1-8-39`. Collected here, built as one batch.

1. **Rename "Mark" in the right-click menu.** "Mark" is wrong: the writer isn't marking anything,
   they're asking the AI to find sentences. Proposed: **Find ▸ Weakest Sentences / Long Sentences**,
   and the result card "1 sentence found" (was "1 sentence marked"). Esc still clears.
2. **History: the original version gets its own icon.** Keep the pencil for the writer's versions and
   the sparkle for AI versions; the ORIGINAL (first) version gets a distinct icon. Proposed:
   SF Symbol `doc.text` (a page — "where it started").
3. **"Add Alternative…" sounds like adding, not replacing.** The right-click item puts new text in
   place of the selection (the original stays in History), so the name should say replace.
   Proposed: **Replace With…** on the right-click menu; inside History the field placeholder becomes
   "Type a replacement" to match (the small "Add +" there stays — it adds a version to the list).
4. **"Rewrite" has no direction.** Trim and Cut in half say what they accomplish; "Rewrite" doesn't
   (rewrite how?). No free-form chat box (that's what ChatGPT itself is for). Owner rejected
   "Clearer / Simpler" and "Easier to Read / Plain Language / Friendly" as meaningless. Researched
   2026-11-14: Google Docs uses Rephrase, Shorten, Elaborate, More formal, More casual; Apple Writing
   Tools uses Rewrite + Friendly / Professional / Concise; Notion uses Improve writing, Make shorter,
   Simplify language, Change tone; Grammarly uses Improve it, Shorten it, sound more professional /
   friendlier, make it simpler. The shared paradigm: a LENGTH group, a TONE axis of formal ↔ casual,
   and one "say it differently" item. Approved by the owner 2026-11-14:
   Rewrite ▸ Trim · Cut in Half · ─ · **Rephrase** (same meaning, different words — replaces today's
   Rewrite) · **Simplify** (simpler words and sentences) · **More Formal** · **More Casual**.
5. **Code check / code review — considered, NOT doing (owner agreed 2026-11-14).** Code in a
   Lineform document is mostly snippets inside writing; real coding happens in an IDE whose
   compilers and linters check it reliably and locally. A model "fixing" code it can't run is
   confidently wrong in ways a reader can't see, and the AI path deliberately excludes code (prose
   segments only; code and front matter are protected and never rewritten). Broken math already
   shows as a render failure. If it ever returns, the only acceptable shape is flag-only, one block,
   never rewriting. Don't re-propose without a user asking for it.
6. **Proofread must show each correction, not a rewritten paragraph.** Owner fixed four separate
   words across a long multi-sentence paragraph; Proofread struck the WHOLE paragraph and put a new
   one underneath — which looks like a rewrite and destroys trust ("did it change sentences?").
   Cause: the review strikes every sentence that differs, and each of the four sentences had one
   corrected word, so every sentence (= the whole paragraph) was struck.
   Proposed:
   - **Proofread = one suggestion per correction**, Google Docs-style: the wrong word struck (dim)
     with the fix highlighted right after it, IN PLACE in the sentence (never moved to a new line).
     Each correction is accepted or rejected on its own. Card: "Proofread · 2 of 4", Reject /
     Accept; ← / → step; Return accepts the current one and moves on; Esc rejects it and moves on;
     ✕ ends, keeping what was already decided. **Accept All** (owner approved 2026-11-14) accepts every remaining correction at once.
   - **Rewrite family stays ONE decision** (Trim, Cut in Half, Rephrase, Simplify, More Formal,
     More Casual), but is SHOWN at the smallest unit that actually changed: unchanged sentences
     stay plain; each changed sentence shows struck + highlighted replacement right after it. A
     whole paragraph shows as replaced only when all of it changed or it was restructured; in a
     multi-paragraph selection, unchanged paragraphs are untouched.
   - Readability: struck text dimmed but legible; each replacement gets its own highlight.
7. **The "1/2" version counter is hard to read at small text sizes.** It is drawn as a small
   superscript INSIDE the passage's blue selection, so at smaller type it's tiny and sits on blue.
   Proposed (owner's idea): draw it just OUTSIDE the highlighted box, on the page background, so
   it isn't on the selection colour; give it a minimum size (about 11 pt) so it never shrinks
   below legible however small the body text is; full-strength ink (Theme.readableInk). Same
   treatment in light and dark, all themes.
