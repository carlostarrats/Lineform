# Files sidebar

The Files tab: scanning, watching, virtualization, file operations, and the sidebar visual system.

Extracted from `CLAUDE.md` so the always-loaded file stays scannable. Content is verbatim —
these are the same load-bearing notes, not a summary. Read this file before changing anything
in this area.

- Files sidebar file management: the Files tab live-refreshes while visible via a recursive FSEvents watcher per root (`Lineform/Outline/DirectoryEventMonitor.swift`, started/stopped with Files-tab visibility so the iCloud-laziness invariant still holds; both roots also re-scan on tab appearance). Own-process events are deliberately **not** filtered (no `IgnoreSelf`) so autosave/Save As keep the tree and a Date Modified sort current; churn is tamed by FSEvents coalescing plus a publish-only-on-change guard in the store's refresh paths, and — because the recursive `items(in:)` walk runs on the main thread — the monitor-driven rescan is additionally **trailing-debounced** (Task 5, `docs/superpowers/specs/2026-07-05-sidebar-scan-debounce-design.md`): the two FSEvents `onChange` closures route through `scheduleWorkspaceRescan`/`scheduleICloudRescan` (injectable `directoryRescanDebounce`, default `directoryRescanDebounceInterval` 0.75s — which **MUST exceed** `DirectoryEventMonitor.coalescingLatency` 0.5s so continuous autosave-while-typing churn keeps resetting the timer and the walk defers to a single settle-after-pause instead of hitching typing ~every 0.5s), cancelled in `endWatchingForExternalChanges`/`deinit`, with a `> 0` synchronous fast-path (interval 0) so tests stay deterministic. Only the monitor path is debounced; every user-initiated refresh (init, Files-tab appear, sort change, hidden-folders toggle, `setWorkspaceURL`, and the `refreshRoots(affecting:)` rename/delete broadcast) stays instant. Moving the walk off-main is the sanctioned follow-up if a huge-tree pause-settle is ever felt (`items(in:)` is already a pure static fn); it was deliberately NOT done in v1 (highest concurrency risk in this incident-prone area). **UPDATE (Task 5, 2026-07-05): the debounce AND the off-main scan were both correct hygiene but NEITHER was the felt fix on a large workspace — a `sample` profile of the live app showed 71% of main-thread time in SwiftUI view layout (`NSHostingView.layout` → AttributeGraph), not the scan. The real cause: the file tree rendered with recursive NON-lazy `VStack`s and folders default expanded, so a big workspace laid out ~3,840 rows at once and re-laid-them-out on every file switch/republish. Fixed by VIRTUALIZING the tree: `OutlineSidebarView.visibleFileRows(_:collapsedIDs:)` flattens the visible rows depth-first (children only when expanded) into `[OutlineFileTreeFlatRow]`, rendered in a `LazyVStack` so only viewport rows lay out — fast whether collapsed or fully expanded. `OutlineFileTreeNodeView` is now a single flat row (recursion removed; it keeps indentation-by-`depth`, collapse toggle, selection, hover, context menu, accessibility). If you add tree UI here, keep it flat+lazy — do NOT reintroduce recursive `VStack`/`ForEach` for children, or a large workspace freezes again. The scan (off-main + debounced) is retained as hygiene.** Each section (iCloud, workspace) has its own persisted **Sort** row (Name / Date Created / Date Modified — deliberately no Manual; `OutlineFileSortOrder`); a sort change on a live root re-SCANS rather than re-sorts, because the 80-per-folder cap is applied in display order (order decides membership). Right-click on rows: **Rename...** / **Delete...** / **Show in Finder** for files, **Rename...** / **Show in Finder** for folders (no folder delete, by design), with native SwiftUI `.alert` dialogs (one `.alert` driven by the `SidebarFileDialog` enum, presented from `EditorContainerView` — deliberately **not** `NSAlert`, which stamps the app icon; only the rare error path uses `NSAlert`). Rename preserves the extension; delete is **trash-only** behind a confirmation whose Cancel is the Return default (the destructive Delete never triggers on Return). File → **Rename...**/**Delete...** menu items act on the current file (disabled for untitled, via `LineformCurrentFileMenuState`). Rename/trash are deliberately **uncoordinated** (`SidebarFileOperations`): main-thread `NSFileCoordinator` writes against the open document's own presenters can deadlock, and presenter-observed trashes make `NSDocument` follow the file into the Trash where autosave resurrects it. Windows retarget instead via `sidebarItemRenamed`/`sidebarFileDeleted` broadcasts (rename re-points the reload watcher with baseline-preserving `DocumentReloadController.noteMoved`, never `register`; a deleted open file becomes untitled-with-content) and sidebars refresh via `refreshSidebarFiles` scoped to the affected root. `@Published` didSet observers **do** fire for assignments in `OutlineFileBrowserStore.init`, so persisted prefs load via direct `Published(initialValue:)` backing-storage init — never plain assignment (that would run the init-forbidden iCloud scan when Show Hidden Folders is persisted on). A deferred change-count re-clear in `LineformSidebarFileOpener.replaceCurrentDocument` prevents SwiftUI's async binding registration from spuriously dirtying freshly swapped documents (the phantom "unsaved changes" prompt).

- Sidebar visual system (nav cleanup, 2026-07-17, `OutlineSidebarView`): every section aligns its icons to ONE **icon column** (`sidebarIconColumnLeading`, 24pt from the sidebar content edge) — tab icons, the bottom Settings row, outline rows, the Files sort icon, root icons, and file/folder icons all share it; disclosure chevrons hang in the reserved slot to its left (`filesChevronSlotWidth`/`filesChevronToIconGap` — a small glyph right-aligned in a wider slot, used by BOTH root headers and tree rows via `OutlineFileRootRow.rootLeadingContent` so the two never drift). **Keep new sidebar UI on this icon column** — don't reintroduce per-section insets or ad-hoc chevron geometry. The three tabs (Outline/Files/Markdown Basics) and the **Settings** row carry **no pill** — state is text color only via `OutlineSidebarView.tabTextColor`: a tab reads darkest when selected (i.e. brightest in dark chrome), a quiet grey otherwise that **darkens** on hover; Settings is the reverse (dark by default, **lightens** on hover). **Every sidebar sub-view (`SidebarTabButton`, `OutlineSidebarRow`/`OutlineSidebarNodeView`, `OutlineFileBrowserView`, `OutlineFileRootRow`, `OutlineFileTreeNodeView`, `OutlineMarkdownBasicsTabView`'s `CopyButton`) takes `usesDarkChrome` THREADED from the theme — it must not read `@Environment(\.colorScheme)` for color.** A nested SwiftUI control re-derives `colorScheme` from the window's `effectiveAppearance`, which drifts to light on the tab/inspector transition (see the multi-document tabs bullet), so an ambient read renders near-black-on-near-black (invisible) selected tab text and file rows on a dark theme. Only the root `OutlineSidebarView` reads ambient `colorScheme`, and only because `EditorContainerView` injects the theme value directly onto it (`.environment(\.colorScheme, …)`); it threads that value down to every child. Symmetric `tabDividerGap` under the tabs, matched by each tab-content's top inset. **Outline rows** get a hover bar; clicking a heading scrolls it to the top of the page **without selecting it on the page** (`MarkdownTextViewRepresentable` collapses the requested selection to a zero-length caret) and bolds it — confirmed by the scroll-settle report, which reads the visible-top character a little BELOW the exact edge (`LineformTextView.visibleTopProbeInset`, must exceed `scrollCharacterRangeToTop`'s 8pt park margin) so the clicked/scrolled-past heading wins over the line sliver above it. Bold is a direct weight swap (a crossfade was tried and reverted — font weight can't interpolate, so it ghosts). **Files rows**: the sort row darkens on hover and its menu is an **inline `Picker`** so the checkmark sits in the OS native selection gutter (matching the Reading-Experience Font menu) rather than a hand-rolled `Label(systemImage:"checkmark")`; root headers are quiet labels (no hover fill) with a leading folder/cloud icon; subfolders read a step lighter (`secondaryTextColor`) and darken toward primary on hover; `.md` file rows keep the accent selection + hover fill unchanged. The workspace action button is the near-black CTA only for first-run **"Choose"** (`isChooseAction`); once a workspace is assigned, **"Change"** is a quiet light grey. **Markdown Basics** section headers match the Files sort label (size 12, medium, inactive-tab grey) and left-align to the boxes, with generous section/header spacing (`OutlineMarkdownBasicsTabView`).

- Show hidden folders: a per-app **View menu** item, **Show Hidden Folders** (⌘⇧., default off, persisted) that reveals dot-directories (`.claude/`, `.agents/`, `.github/`, …) and their Markdown/text files, de-emphasized. `node_modules` and `.git` stay excluded regardless (`excludedDirectoryNames` in `OutlineFileBrowserStore`). Toggling re-scans; hidden files open/watch/render like any other. The menu checkmark is driven by the shared `HiddenFoldersMenuState` (backed by the same `showsHiddenFoldersDefaultsKey`); toggling broadcasts `LineformAppNotification.toggleHiddenFolders` app-wide. A window applies it to its per-window store **only while its Files tab is visible** (the observer lives on the Files-tab view, not the always-present sidebar), and otherwise reconciles on the tab's next `.onAppear`. This deliberately preserves the iCloud-laziness invariant above: the store's expensive scan still only runs when the Files tab is shown, never for windows on the Outline tab or with the sidebar collapsed. (There is no in-sidebar toggle; the older eyeball button was removed.)

- Info sidebar tab: a third Files-sidebar tab (**Outline / Files / Info**, `OutlineSidebarTab.info`) that renders the Markdown syntax reference beside the writing surface, so syntax help is available while typing in **any** mode. It **replaced** the former blocking in-window **Info modal** and its `info.circle` toolbar button (see `docs/superpowers/specs/2026-07-05-info-sidebar-tab-design.md`). Copy is a pure data model (`MarkdownReference` in `Lineform/Outline`, kept concise by `MarkdownReferenceTests`) rendered by `OutlineInfoTabView`: rows are **stacked** (monospaced syntax over a plain-English explanation, not two columns — the sidebar is narrow), section-ruled, and theme-aware. Syntax reuses the sidebar's primary text color; the explanation uses an **AA-safe muted tone** — the sidebar's own light secondary dips to ~3.8:1 against the light page (fine for short Files labels, too low for longer-form reading), so `OutlineInfoTabView.explanationLightWhiteComponent` bumps **only** the light tone darker (0.36 → ~4.9:1) while **reusing** the sidebar's dark secondary (already AA); guarded by `OutlineInfoContrastTests`. The tab is **static content** — no directory scan, no FSEvents watcher — so it preserves the iCloud-laziness invariant (only the Files tab scans). Removing the modal renamed its shared dimming scrim `MarkdownBasicsOverlay` → `MuseModalScrim` (Settings still uses it); the toolbar is left with only the Reading Experience toggle (`EditorToolbarAction`).
